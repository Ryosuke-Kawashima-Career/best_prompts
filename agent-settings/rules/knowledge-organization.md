# Learning-Agent Guide

Use this guide for every learning request in this project.

## Output format

- Produce the deliverable as a Markdown (`.md`) file unless the user explicitly asks for chat-only output. You should add your output in the **one** markdown files or **designated** ones of each directory. You should organize the order of the contents on the file of each directory for learning.
- Use a clear title, a short purpose statement, descriptive headings, and concise formatting.
- Write in the language requested by the user. When no language is specified, match the source material or the user's language.
- Prefer practical, reusable learning notes over a bare answer.

## Learning materials

When explaining a topic, structure the note as follows when relevant:

1. **Core idea** — a plain-language definition.
2. **Step-by-step explanation** — break the reasoning or process into small, numbered steps.
3. **Worked example** — show the idea applied to a realistic example.
4. **Common pitfalls** — identify likely misunderstandings and how to avoid them.
5. **Practice problems** — include questions that progress from basic understanding to application.

Keep explanations accurate, direct, and connected to the learner's goals, especially IELTS communication and logical/business thinking when relevant.

## Practice-problem requirements

- Provide a mix of recall, reasoning, and application questions when the topic allows.
- State any assumptions or data required to solve a problem.
- Put every answer in its own collapsible Markdown toggle immediately below its question.
- Each answer should include the conclusion, a step-by-step solution, and a short explanation of why the method works. Add an example if it would improve understanding.

Use this Obsidian-compatible pattern:

```markdown
### Problem 1: [Question title]

Question text.

> [!answer]- Show answer and explanation
> **Answer:** [short conclusion]
>
> **Step-by-step:**
> 1. [First step]
> 2. [Second step]
> 3. [Conclusion]
>
> **Example:** [A brief practical example.]
```

For multiple-choice questions, explain why the correct option is correct and why the most tempting incorrect option is not.

## Quality check before delivery

- Confirm the file is valid, readable Markdown.
- Confirm every practice question has its own collapsed answer toggle.
- Confirm each non-trivial answer includes clear steps and, where useful, an example.
- Avoid unexplained jargon, overly long paragraphs, and answer-only problem sets.
